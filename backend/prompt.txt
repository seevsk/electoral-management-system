Ajustes necesarios:

1. Elección presidencial
El combo de elecciones del formulario de candidatos debe mostrar solo elecciones presidenciales disponibles.
Si ya existe en ElectionRepository un método como:
findAvailablePresidentialElectionsForCandidates()
úsalo en CandidateServiceImpl.
No debe traer elecciones de otros tipos.

2. Un candidato por partido y elección presidencial
Además de validar:
- mismo votante en misma elección
- mismo número de lista para mismo partido y elección

también debe validar:
- no se puede registrar más de un candidato para el mismo partido en la misma elección presidencial.

Si ya existe una relación en party_election_representatives con ese party_id y election_id, bloquear el registro con este mensaje:
"Este partido ya tiene un candidato asignado para esta elección."

3. Foto opcional
La foto del candidato debe seguir siendo opcional.
En registro:
- Si photoFile == null o photoFile.isEmpty(), guardar photo_url como null.
- No llamar a Cloudinary.

En actualización:
- Si no se sube nueva foto, mantener la photo_url actual.
- Si se sube nueva foto, recién llamar a Cloudinary.

4. Manejo de errores Cloudinary
Si Cloudinary falla, no debe salir Whitelabel Error Page.
Debe volver al formulario con un mensaje controlado.
No imprimir ni exponer CLOUDINARY_API_SECRET.

5. party_election_representatives
Al registrar candidato, debe crear o sincronizar la relación en party_election_representatives.
Al actualizar candidato, debe mantener coherencia con party_id, election_id y candidate_id.
No usar parties.representative como fuente principal.

6. Restricciones
No modificar migraciones Flyway.
No modificar tablas.
No tocar el CRUD de partidos.
No tocar login.
No usar React ni Angular.
Mantener Thymeleaf.
No cambiar rutas existentes.
